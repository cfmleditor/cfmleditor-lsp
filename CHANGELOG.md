# Changelog

## [Unreleased]

- Add `formatting.parenSpacing`, which decides the padding inside parentheses: `"pad"` for `if ( a )` and `foo( 1, 2 )`, `"tight"` for `if (a)` and `foo(1, 2)`. There was no setting for this and the formatter did both — conditions, `for`/`while` headers and grouping were padded, call and parameter lists were not, each hardcoded in a different place. Left unset it still does exactly that, byte for byte, so no existing project is reformatted; setting it is how a project asks for one rule in both positions. Checked against the six-project corpus in all three modes: 5,624 files, 5,563 clean, the same 2 guard rejections and 2 non-idempotent files in each, and with the setting unset no file changes verdict against the pre-change baseline.

- Fix a data race on the client-reported workspace roots. `indexWorkspace` read the slice directly from the goroutine `handleInitialize` spawns, while `workspace/didChangeWorkspaceFolders` appended to it from the handler — so a client adding or removing a folder while the first index was still running raced with it. Pre-existing, and found by CI's race detector once a test drove both halves. The field now has a mutex of its own, deliberately not the server's main lock: the roots are read through `searchRoots`, which is reached from `getResolver` and so from most of the server, and nesting those reads inside the main lock would put an ordering constraint on almost every path.

- Fix the workspace roots the client reports at `initialize` being converted with `URI.Path()` rather than `cfpath.FromURI`, the last inbound boundary left on the old conversion after 0.2.8 (#45). For the canonical Windows form `file:///c%3A/Users/q/proj` it produced `/c:/Users/q/proj` — a leading slash that is not a Windows path — and these roots are what `searchRoots` falls back to when no config names any, so a wrong one sends every workspace-wide search somewhere that does not exist. Both the `initialize` handler and `workspace/didChangeWorkspaceFolders` now use `cfpath.FromURI`, which also keeps the added/removed forms matching the stored ones.

  Not fixed, because it cannot be at this layer: the non-canonical `file://C:\Users\q\proj` that some clients send is rewritten by `go.lsp.dev/protocol` while unmarshalling — the whole path is read as the URI's authority and re-serialised lowercased with a trailing slash — so the path is gone before any handler runs, and the root ends up `/`. `TestUncanonicalWindowsRootIsMangledUpstream` records that boundary and fails if the library's behaviour changes.

  A root that converts to `/` or the empty string is declined outright, with a warning naming the URI it came from. `/` is not a workspace, and since `searchRoots` hands these roots to `findRefs` and `scanWorkspace`, keeping one had a "find all references" walk the filesystem — with the guard removed, the indexer duly starts crawling `/` and trips over `/proc`. Nothing found is the better answer, and the warning is what makes an otherwise silent mangling diagnosable.

- Fix every workspace-wide search covering nothing in a session with no `.cfmleditor.json`. `WorkspaceFolders` is the *configured* set — it comes from `workspacePaths` and is empty without a config file, which since daemon mode became opt-in is the ordinary standalone case — and eight places read it directly to decide where to look. `cfmleditor.findRefs` answered `0 match(es)` for a function with three callers in the same folder; `cfmleditor.scanWorkspace` reported `0 parse errors in 0 files`; `cfmleditor.copyPackage`, go-to-definition's workspace-relative file fallback, document-link resolution, `Application.cfc` bean discovery and the resolver's own component-path search all skipped their workspace pass. None of them failed — they reported nothing found, which is indistinguishable from there being nothing to find.

  They now go through `searchRoots()`, which falls back to the roots the editor opened, as `indexWorkspace` and `textDocument/references` already did. The configured set is still the right question for membership (`isWorkspaceFolder`) and for whether the inclusion filter applies at all (`isIncludedPath`), so those keep reading the field.

- Fix `formatting.lowercaseTags: false` not working. The setting says "do not change my tag casing" and the formatter changed it anyway, in two different ways depending on how the grammar happened to parse the tag. A tag the grammar has a node kind for — most of them — had its name rebuilt from that kind, which is lowercase by construction and never consulted the setting at all, so `<CFOUTPUT>` came back `<cfoutput>`. A tag that fell to the generic path did read the source, but rebuilt the name as a hardcoded `cf` plus whatever followed, so `<CFDUMP>` came back as the mongrel `cfDUMP`. A third group — `cfif`, `cfelse`, `cfelseif`, `cfcomponent`, `cfscript`, `cfquery` — is written from string literals in the emitters and was always lowercase. IntelliLucee exposes this as a checkbox, so unticking it did nothing useful.

  `tagName` is now purely the tag's canonical identity — always lowercase, whatever the setting — and what to write is a separate pair of helpers that read the source's own spelling. That split also closes a latent bug: `firstBodyChildIsArg` compares `tagName` against the bare literal `"cfargument"`, which stopped matching when the setting was off, so a blank-line rule changed with an unrelated casing preference. Opening and closing halves are read separately, since CFML does not require them to agree and `<CFOUTPUT>…</cfoutput>` is legal. A spelling that does not case-fold to the canonical name is discarded, so a miscounted offset can only ever fall back to the old output rather than emit some other tag.

  Checked against the six-project corpus both ways: 5,624 files, 5,563 clean, the same 2 guard rejections and 2 non-idempotent files as before, and no file changing verdict — with the setting on (the default path, which must be byte-identical) and with it off (the path this adds, where every uppercase tag in the corpus now takes the new route).

- Fix unrelated projects sharing one daemon, and so one index. `daemon.FindConfig` returned a `Config` with an empty path and the working directory's base name as its `Name` when its walk found no `.cfmleditor.json`, rather than reporting that it had found nothing. Two consequences: the standalone branch in `runServer` became unreachable, so every session started a daemon whatever it found; and since the socket path is a hash of `Name`, the daemon was keyed on the base name of the working directory. Two projects in folders both called `app` shared a daemon — and an editor that starts the server without setting a working directory, as the IntelliJ plugin does, gave every project on the machine the same name, so all of them did. Reproduced end to end: with two config-less projects open, go-to-definition in one resolved a call to a function that exists only in the other. It returns nil now, which every call site already tested for, so a session with no config file runs standalone with its own index — and a project that wants the sharing says so with a `workspaceName`.

- Fix a project's own `.cfmleditor.json` being ignored in favour of the daemon's. The two searches start in different places — the daemon walks up from the process's working directory, a session walks up from the workspace roots the editor reported — so a project config sitting under the folder the editor opened was masked by whichever config the daemon happened to pass on its way up. The nearer one governs now. The two config paths this had grown into are one function (`configureSession`), which also closes the case where the daemon's file has since become unreadable and the editor's `initializationOptions` were dropped with it, silently, on the one path that exists to apply them.

- Fix `textDocument/references` scoping a qualified call by the current file's own same-named function. `dao.save()` names a receiver, so it is not calling the `save()` its own component declares — but with the receiver unresolved the declaration lookup fell through to "prefer this file", and the search then returned that component's callers instead of the DAO's. Go-to-definition has always excluded the current file at this point for the same reason.

- Fix a search root that cannot be stat'ed taking down a whole reference search. `filepath.Walk` reports such a root with a nil `FileInfo` and `collectFiles` dereferenced it, so one stale `workspacePaths` entry — or a folder removed since the editor opened it — turned every Find All References into an internal error rather than a result from the roots that are there.

- Fix `completions` having the same defect `formatting` was just fixed for: its three settings were plain bools, so `{"completions": {"tagSnippets": false}}` also switched off `functionSnippets` and `globalFunctionResolution` — naming one setting silently disabled the two it did not name, including the one whose loss breaks go-to-definition for unqualified cross-file calls. They are `*bool` now, the block merges key by key, and an empty block states nothing rather than meaning all-false.

- Fix the editor-settings overlay replacing the daemon's formatting configuration with a zero value when neither the config file nor the editor payload mentions `formatting`. `config.Resolve` leaves an absent block at its zero value deliberately, which is not what `daemon.Config` resolves for the same file — its accessors apply each field's default whether or not the block exists — so the overlay was handing the session `WhitespaceOnly: false`, the formatter's safety guard, off.

- Gate `cfmleditor.format` on `formatting.enabled`, the same check `textDocument/formatting` has always made. Without it the command handed `s.Formatting` to the formatter whatever it held, and an unconfigured one is the zero value — every flag false, `whitespaceOnly` among them. That is what made a zero-valued formatting config dangerous rather than merely inert, and it is the entry point the IntelliJ plugin's Format Document action uses.

- `textDocument/references` no longer drops a component reference whose line does not spell the component. A `componentResolver` establishes references from expressions that never name the resolved path — `svc = getPageTools()` is a reference to `packages.tass.pagetools` — so dropping them lost most instantiation sites in exactly the resolver-configured projects this server exists for. The receiving variable is the fallback anchor; an entry with neither on its line is still dropped rather than returned as a whole-line match. The scan also reads the editor's copy of any open file now, so a search run with unsaved changes no longer reports line numbers from the saved text.

- Fix a `.cfmleditor.json` naming a single `formatting` key discarding every formatting setting the editor sent, and switching the formatter off with them. `config.Merge` replaced the whole block rather than merging it key by key, which reads as "the file wins" but means something far stronger. That is how an IDE configures the formatter when it has no config file of its own to write: IntelliLucee, the IntelliJ plugin, sends all fourteen settings from its settings UI as `initializationOptions`, so one `"formatting": {"lineWidth": 120}` in a project reverted the other thirteen to their defaults — and because `enabled` defaults to false, `textDocument/formatting` then returned no edits at all and format-on-save silently stopped working. `formatting.enabled` and `formatting.debug` are now `*bool` like every other flag in the block, so "the file turned this off" is distinguishable from "the file did not mention it", and the merge is field by field with a reflective test that fails when a new field is added and not wired in.

- Merge the editor's `initializationOptions` in every session, not only those whose daemon found no config file. They are per-session and the daemon never sees them, so skipping them whenever a config file happened to be found made an editor's settings apply or not depending on which directory its process was started from — IntelliLucee starts the server with no working directory of its own, so that is whatever the IDE inherited. A session the daemon configured now re-resolves from the daemon's own config file plus the editor's payload and applies the result once (`overlayEditorConfig`), rather than layering a second partial application on top: `applyConfig` appends resolvers and keeps the first map it is given, both of which assume it runs once.

- Replace the condition that decided whether a session loads `.cfmleditor.json` at startup. It was `len(s.ComponentResolvers) == 0`, standing in for "has this session been configured already" — so an unrelated config key decided unrelated behaviour, which is how the completions defaults came to be dropped for some workspaces and not others. The session now carries the path of the config the daemon read (`Settings.ConfigPath`), and looks for one itself exactly when it was handed none.

  Getting that right turned on something worth writing down: `daemon.FindConfig` returns a `Config` with an empty path rather than nil when its walk finds no file, so `runServer`'s `cfg != nil` is always true, the standalone branch below it is unreachable, and `Settings.Apply` runs for every session whether a config exists or not. A flag meaning "Apply has run" is therefore not the same question as "is this session configured", and using one silently switched off editor `initializationOptions` for every session without a config file — the documented way to configure the server without adding a file to the project. The two walks also start from different places: the daemon's from the process's working directory, the session's from the workspace roots the editor reported, which can sit under a config the first walk never passed. An empty `ConfigPath` is the condition that gets both right.

- Make `cfmleditor.findRefs` write its report only when asked. It wrote `refs-<name>.md` and `refs-<name>.dot` on every invocation, into the directory of the file the request came from — so the caller that fires most often, a code action on an ordinary "find all references" gesture, left two files beside the source being read, inside the repository, ready to be committed by accident. The command returns the same summary to the client either way, so the files duplicated something the caller already had in hand. A third argument now asks for them; the two-argument call every existing client sends does not write, and neither does an explicit `false`. The export stays reachable from any client through a code action of its own ("Export references to X to a file"), which is separate from the two plain actions precisely because it is the one that puts files in the user's source tree. `cfmleditor.exportDeps` is unchanged — exporting is what it is for, and its name says so.

- Fix every daemon session running with `globalFunctionResolution`, `tagSnippets` and `functionSnippets` off, whatever the config said. All three default to `true`, but that default lived only inside `config.Resolve`, and a daemon session does not go through it: it is configured from `server.Settings`, which carried `linting` and `formatting` but had no fields for these three at all. `handleInitialize` hid it for some workspaces — it loads the workspace config itself when a session arrives with no component resolvers, which quietly repaired them — so the symptom was that adding a single unrelated `componentResolver` to a working `.cfmleditor.json` turned off go-to-definition for every unqualified call to a function in another file, along with both kinds of completion snippet. Confirmed against the built binary: with one `componentResolver` added and nothing else changed, go-to-definition on an unqualified call went from resolving to returning null.

  The same three were also lost on a second path, in standalone mode with neither a config file nor editor `initializationOptions`: `loadWorkspaceConfig` returns before it reaches `applyConfig` when it finds neither, so nothing ever wrote them. `NewServer` now starts from the documented defaults, so a session that never runs `config.Resolve` still behaves as documented rather than as the zero value reads.

  The defaults themselves now live in one place (`config.ResolveCompletions`) instead of being restated by each caller, and the daemon's `Settings` construction moved out of `package main` into `daemon.SettingsFrom`, where a test can reach it. A key read from config but never copied into `Settings` reaches no daemon session and reports nothing — it looks exactly like a key the user did not set — so that construction is now checked field-by-field reflectively against a config that sets everything, the same guard `Settings.Apply` already had on the next hop.

- Add `textDocument/references`, behind `"references": {"enabled": true}` in `.cfmleditor.json` (off by default). The capability is advertised only when the flag is on, so a workspace that has not opted in never sees "Find All References" offered and the handler declines the request if one arrives anyway. It is a flag rather than a plain capability because of the cost: one request walks and parses every CFML file under the search roots — the same scan `cfmleditor.findRefs` and the `refs` CLI already do — since the index stores definitions and refs but no call sites to answer from incrementally. Whether that is acceptable by default on a workspace of a few thousand files is what the flag exists to find out. A dot-path under the cursor (`new models.UserDAO()`, an `extends`, a `<cfinvoke component>`) is matched against component refs; anything else is a function name matched against call sites, with `refs`' existing verification hooks so a call to a same-named function on another component is not reported. The search is scoped by the file that *declares* the function, resolved first in the order go-to-definition uses, rather than by the document the request arrived on — which is what lets it be asked from a call site, where the cursor usually is; with no single declaration to pin it to, it falls back to scoping by the requesting document rather than picking one of several same-named candidates. `includeDeclaration` is honoured.

  `refs.Entry` carries a line and no column — nothing that consumed it before needed one — so each result's column is recovered by finding the identifier on its line, whole-word and case-insensitively, counting UTF-16 code units as an LSP character offset requires. Two consequences fell out of that. A component entry whose line does not name the component is dropped rather than returned as a whole-line match: the parser records the variables a component reference flows into as well as where it is written, so `report = myCtrl.getReport()` is a ref to myCtrl's component on a line that never mentions it — the right answer for the `refs` CLI, which reports which variables hold a component, and a jump to an unrelated statement here. And the declaration returned for `includeDeclaration` is anchored to its name too, rather than to column zero as go-to-definition leaves it, so it is not the one entry in the list highlighted differently from the rest.

- Fix `TestParsePerformance` failing on an idle machine, every run. Its comment claimed thresholds of "~3x the baseline" while the numbers underneath left between 3% and 8% headroom, so three of its four cases were red locally whatever the change under test — and a test that is always red is a test people stop reading. Two of the three were not really measuring what they named: `ApplyEdit_InFunc` and `FuncVars` built a fresh `ParseResult` inside the timed region, so what they timed was `Parse` plus a rounding error. `FuncVars` itself costs ~8µs beside the ~185µs `Parse` it was being timed with, which left it unable to notice a 20x regression in itself but able to fail on a 5% slowdown in `Parse`. Setup is now paused out of the measurement the way a `testing.B` does it, the verdict is the fastest of five rounds rather than the mean of one — scheduler noise only ever adds time, so the minimum is the closest to the true cost wall-clock timing can get — and the thresholds are an honest 5x the measured baseline, which is the resolution this kind of test has: it catches a lost memo or an accidental O(n^2), and the benchmarks beside it are there for anything finer. It now passes with the machine oversubscribed two-to-one, and still fails on a tenfold regression. Unchanged: it is skipped under `-short`, so CI's gating jobs never run it and the informational perf job still does.

- Bump the CFLint fallback version from 1.5.14 to 1.5.16. It only applies when the releases API cannot be reached — the normal path queries it and downloads whatever is current — so this is about an offline first run not starting two releases behind. 1.5.16 is the first release carrying CFLint's scan-performance work: on a 6,544-file codebase its native binary goes from 373s to 145s with byte-identical findings, which is the difference between a workspace scan being usable and not. 1.5.15 was never published — CFLint's master carried that number before a release was called off.

- Fix the one case where the formatter silently destroyed a file: a `.cfm` whose body is JavaScript (Lucee ships `jquery.blockUI.js.cfm`, opening `<cfcontent type="text/javascript">`). To the CFML grammar that body is template text, so it is reflowed as prose, and JavaScript's `//` comment means nothing to CFML — a following line is folded up onto it and the code after the comment is commented out. Only whitespace changed, so the `whitespaceOnly` guard passes and the file is written. This is the same class as the `<pre>` carve-out already in FORMATTER-ISSUES.md 3.3 — whitespace is not free in every context — and is long-standing rather than new: the file has been on the not-idempotent list since the original audit, described there by its symptom (the output no longer parses) rather than its cause. One shared `writeText` helper replaces the collapse-and-reflow pair at all four text call sites: a run holding a `//` comment keeps the line structure it was written with, everything else is reflowed as before. It is the carve-out `<pre>` already had (3.3), for the same reason — the guard's premise is that whitespace is free, and in text whose line breaks terminate comments it is not. Reflowing is given up for such a run rather than taught to break safely, which would need `safeBreaks` to stop offering positions after a `//` as well. On the file that surfaced it, source comments still ending their own line go from 4 of 81 to 78 of 81; the remaining three are a different mechanism, described in 3.7, where the comment's own text is tokenised by the grammar (`<--` as markup, `#...#` as an interpolation) and arrives as several nodes. `isLineCommentStart` already declines to read a URL's `//` as a comment, so links in prose still reflow.

- Fix a lone `#` in a script-region string running the `whitespaceOnly` guard's string span to end of file. CFML requires `##` for a literal hash, so inside CFML every `#` is paired — but a `<script>` region is JavaScript, where CFML's rules do not apply and `var s = "#id"` is an ordinary CSS selector. Treating that `#` as an interpolation opener sent the scan hunting for a close that never comes, and with every later position looking like it sat inside a string, no comment was recognised in the rest of the file and the guard stopped checking comment extents at all — the one shape in this area that is a genuine blind spot rather than a false rejection. An interpolation now has to close on the line it opened on. Introduced by the interpolation handling added earlier in this same unreleased block; found by code review, not by the corpus, which contains no case of it.
- Fix a `//` comment among a function *expression*'s parameters or annotations being joined onto one line, where it swallows the closing paren and the brace opening the body. The declaration path breaks the line so the comment ends it; an expression has nowhere to break to, so the construct is reproduced as written. The guard caught both, so neither corrupted a file — the effect was that format-on-save silently did nothing.

- Fix two mistakes in how the `whitespaceOnly` guard's string scanner reads a CFML literal, each of which ran a literal past its own closing quote so the span covered code, where no comment could then be recognised. A backslash is an ordinary character in CFML — a quote is escaped by doubling it and in no other way, so `"\"` is a string holding one backslash (ContentBox has `replace( inPath, "\", "/", "all" )`, and every Windows path written `"C:\dir\"` ends the same way), but the scanner treated `\"` as an escape. And an interpolation may hold strings of its own: Lucee's admin has `"timezone:'#replace(ds.timezone,"'","''","all")#' // ..."`, a double-quoted string whose `#...#` contains three more, and the scanner ended the outer literal at the first of them. `##` is a literal hash and is stepped over rather than read as an empty interpolation. 2 files.
- Fix three comment and separator defects in the formatter's long tail. `<cfset x = /* why */ f()>` lost the comment, while the identical one written after the value survived — `delimitedComments` matched on node kind, and the document grammar gives a `/* ... */` in this position the plain `comment` kind, the same one it gives `//`; the text is what tells the two apart. `cfparam (name:"local.d" default:"DDD")`, a CF tag in script separating attribute from value with a colon, came back with every colon rewritten to `=`, because the helper asked for `=` returned it whether or not the node had one. And `var colTypes = [ "a", "b" ]// note`, a declaration with no semicolon of its own, gained a comma after the array and put its semicolon after the comment where the comment swallowed it — the comment is a named child of the variable_declaration and every named child went into the declarator list. Comments now go on a line of their own there, since trailing the semicolon is not a fixed point.
- Fix two ways an ordinary script-syntax `.cfc` ended up with no script region at all, which switched off `//` comment recognition for the whole file and made the guard compare comment text as though it were code. A leading UTF-8 BOM is not whitespace, so the probe that decides "is this a script component" stopped on it and the keyword check then failed on a file that is plainly `component { ... }` — a leading-comma struct holding a commented-out entry came back as a non-whitespace change reported against the entry *before* it. And a `//` comment's scan for the end of its line looked for `\n` alone, so in a file with classic Mac line endings (a bare `\r`, no `\n` anywhere) the first comment ran to end of file and collected every remaining line as its body; CRLF was never affected. 554 corpus files carry a BOM. 5 files.
- Fix a function declaration's annotations being joined onto one line, so a `//` comment among them — how ColdBox's own test handlers say what each cache setting is for — swallowed every annotation after it *and* the brace opening the body, leaving code that no longer parses. A comment now ends its line and the annotations that follow continue on the next, with the brace given a line of its own when a comment is last. This one was invisible until the two fixes above let the guard see these files at all. 3 files.
- Fix the comment-preservation check missing a comment that survives a rendering but is broken by it: the operand that followed it in the source folded up onto its line, where the comment swallows it. Only whitespace changed, so the character-level comparison could not see it. The check now requires each `//` comment to be both present and still the last thing on its line. 1 file.
- Fix the `whitespaceOnly` guard refusing a correct format because a string literal's `/*` was read as the start of a block comment. CFML code is full of globs that contain one — ColdBox's own build script has `path = "/#libBuildDir#/**"` — and everything from there to the next `*/`, in one case forty lines of code below, was collected as comment body. The swallowed code was still compared, so nothing went unchecked, but it was compared as *comment text*: that comparison folds whitespace and case exactly as the main comparison does and has none of its allowances for the canonicalisation the formatter performs on purpose. A semicolon deliberately added to a `.run()` far below therefore landed inside a "comment body" and the format was refused — reported as changed comment text, naming neither the string that caused it nor the statement that tripped it. String literals are located up front now and no comment may open inside one, with both CFML forms of embedded quote stepped over. 7 files in the formatter corpus, four of which had been reporting changed comment text whose reported bodies were plainly code.
- `tree-sitter-cfml` grammar update (v0.26.34 → v0.26.35), and handle the two cfscript constructs it brings into view. As with the v0.26.34 bump, a construct the grammar starts parsing is one the formatter starts rendering, so each release turns a batch of safe refusals into formatter defects:
  - Two function parameters with no comma between them — `f(struct s = structNew()` newline `boolean ssl)`, which the release parses for the first time (#49) — were merged into a single parameter and rejoined with a space. The grammar accepts a newline between such a pair but not a space, so the formatter's own output no longer parsed. This is the one shape the `whitespaceOnly` guard cannot catch, because only whitespace did change: the file came back *unstable* rather than refused, meaning format-on-save produced a file the next format would reject. The parameter walk now ends a parameter where the next one's first token begins, comma or not, and records whether a comma followed so the separator is reproduced rather than assumed; the single-line renderer, which has no newline to give such a pair, reproduces the list verbatim. 4 files in the formatter corpus.
  - A `//` comment on each operand of a condition joined with `&&` lost every comment but the last, and left that one in front of the closing paren where it comments out the rest of the line. A comment between two operands is neither the `left` nor the `right` field of the binary_expression holding them, so rebuilding the condition from those fields drops it — while the same condition written with `or` keeps them, which is why this went unnoticed. The rendered condition is now checked against the source's own comments and reproduced as written when any went missing, and a short condition carrying a line comment is never collapsed onto one line. 2 files.
  - `Test::["f"]()`, the subscripted form of static access, came back as `Test["f"]()` — the `::` dropped, turning a static call into an instance call on a value that has no such member. The grammar reports the accessor as a named `static_chain` field on the `subscript_expression`, exactly as it does on a `member_expression`; only the latter was special-cased.
  - `throw message="Access Denied" type="MyCustomError";`, the tag form written in script, lost every attribute but the first — deleting the `type` a catch block dispatches on. Each attribute is its own `parameter_attribute` child, and every rendering path read `NamedChild(0)` alone.
  - `component( output=false, javasettings={...} )` lost the commas between its attributes. The parenthesised form separates them with commas while the bare form separates them with spaces, and the commas are anonymous children, so joining everything with a space dropped them. Which attribute carried a comma is recorded now rather than inferred from the form, so neither form is imposed on the other.
  - `describe("x", function() labels="query" { ... })` lost the annotation, which is how TestBox and Lucee's own suite label a spec. It is a child with no field name, and the function-*expression* renderer built its output from name, parameters and body alone — so the same annotation survived on a declaration and vanished inside an argument list.
  - A `//` comment parked before a ternary's `:` was dropped outright, the same root cause as the `&&` condition above and closed by the same fix.
  - Against the six-project corpus the upgrade takes files that format cleanly from 5,531 to 5,547 and grammar refusals from 62 to 54, with guard rejections falling from 25 to 17 and no file moving the other way. With the guard and comment fixes above, the corpus stands at 5,563 clean and 2 guard rejections; FW/1 and TestBox format entirely cleanly, and the 2 remaining non-idempotent files are ones whose formatted output the grammar cannot read back, though the guard confirmed the output is whitespace-only and the file itself unharmed.

- Fix a trailing comma being silently deleted from every list the cfscript formatter renders — `[1, 2, ]`, `{ a: 1, }`, `f(1, 2, )` and `function init(required wirebox, )`. The form is legal in Lucee, Adobe CF and BoxLang, and common in hand-maintained lists because adding an entry then touches one line rather than two. Five renderers each collect the elements and rejoin them with `", "`, reconstructing the separators from scratch, so the source's final comma had nowhere to come back from. The `whitespaceOnly` guard caught it, so no file was ever corrupted — the effect was that format-on-save silently did nothing to any file containing one. The comma is placed after the last *parameter* rather than at the end of the rendered list, because a comment can sit anywhere a parameter can, including after the list's final comma, and a separator written past one lands inside the comment. The allowance also moved off `selfCloseTags` — which has nothing to do with quoting and was disabling the check for whole files — onto `doubleQuoteAttributes`, the option that performs the re-quoting.
- Record in `FORMATTER-ISSUES.md` what the grammar refusals actually are: eight confirmed `tree-sitter-cfml` cfscript gaps reduced to minimal repros and re-verified standalone (`access:remote` annotations, `final` members in a `static` block, `component( javasettings = {} )`, `default` interface methods, bare `param x.y;`, body-less tag-in-script, inline `java {}` classes, arrow functions with statement bodies), plus a document-grammar gap where `final component` in a `.cfc` degrades to plain text instead of an `ERROR` node — so the body is emitted unformatted, the guard passes it, and the corpus scores the file clean. Also notes which of the remaining files are Lucee's own deliberately-invalid fixtures rather than gaps.

- Force the pinned toolchain for `make vuln` too. `go run golang.org/x/vuln/...@v1.7.0` resolves the toolchain the *scanner* module asks for rather than the one this module targets — "requires go >= 1.25.0; switching to go1.25.13" — and a govulncheck built with 1.25 cannot load a 1.26 module's packages: it reports every package as "requires newer Go version" and scans nothing, while still exiting non-zero as though it had found something. CI never saw it, because `setup-go` installs the version from `go.mod` as the local toolchain and no switch happens; anyone whose own Go is older than the target hits it on the release gate. Same one-line fix as the linter got, reusing the `GO_VERSION` the linter already reads out of `go.mod`.

## [0.2.5]

- Fix the formatter changing non-whitespace content. Audited by formatting 5620 CFML files from Lucee, ContentBox, ColdBox, FW/1, TestBox and cfmleditor: 1671 were rejected by the `whitespaceOnly` guard, so with the default settings the LSP silently declined to format them and format-on-save did nothing. 5450 now format cleanly and 84 are still rejected. Each of the following was a separate defect, and most of them destroyed or altered code rather than merely tripping the guard:
  - `query` and `function` return types were dropped outright: `public query function GetData()` came back as `public function GetData()`. The signature prefix was gated on `IsNamed()`, but the grammar tokenises those two type names as anonymous keyword nodes. The other fourteen return types, and dotted component paths, were unaffected.
  - A `try` with more than one `catch` kept only the first and deleted the rest *along with their bodies*, because every catch clause carries the same `handler` field name. The exception type was dropped too — `catch (java.lang.Exception e)` became `catch (e)`, silently widening what the handler catches.
  - `interface {}` was rewritten as `component {}`, changing what the file declares, and the `abstract` and `final` modifiers were dropped. The component header was hardcoded to `"component"`.
  - Attributes written after the parameter list were hoisted in front of the `function` keyword, so `function setup() localmode="true" {}` became `localmode="true" function setup() {}` — output that does not compile. Seen with `localmode`, `skip`, `restpath`, `httpmethod`, `output` and `hint`.
  - A `//` comment inside an array or struct literal, or among a call's arguments, was treated as an element and joined inline with `", "`, so it commented out everything after it and destroyed the statement. Comments were also deleted outright between a block and its `else`/`catch`/`finally`, and between a chained call and its next `.hop()`.
  - Lucee and BoxLang static access `Widget::getData()` was emitted as the instance call `Widget.getData()`.
  - A leading UTF-8 BOM was stripped from every file that had one (554 in the corpus). It sits outside every CST node, so the walk never emitted it.
  - CF tags that are legal without a body — `cfmodule`, `cfhttp`, `cfinvoke`, `cffeed`, `cfadmin` — were given a closing tag they never had, which re-parented every following sibling into the tag's body.
- Refuse to format a document the grammar cannot parse, instead of emitting corrupt output. A body-less `<cfinvoke>` or `<cfhttp>` inside `<cfcomponent>` produces an `ERROR` node, which the node walk had no rendering for; it fell through to a raw emit that ran the tag name and every attribute together (`<cfinvokecomponent="..."method="..."`), dropped `</cfcomponent>` and appended a bogus `</cf>` — and returned a `nil` error while doing it.
- `cfmleditor-lsp format` no longer corrupts files. It built `DefaultOptions()`, which leaves `whitespaceOnly` off, and never checked the tree for parse errors, so it wrote that corrupt output over the source and exited 0 — 110 bytes vanished from a test fixture, leaving it unparseable. The guard is now on by default, matching the LSP, with `--allow-non-whitespace` to opt out; a file is only rewritten after formatting succeeds, and a batch run reports every failing file rather than exiting on the first.
- Let the `whitespaceOnly` guard accept the canonicalisation the formatter performs on purpose. Adding braces around a single-statement body and a semicolon to a statement written without one are both non-whitespace changes, so the guard rejected them and the formatter was in conflict with its own default — 527 real-world files, 9.4% of the corpus. The guard now skips an inserted `;`, `{` or `}` on the output side, in the same spirit as the existing self-closing-slash and quote allowances. The allowance is one-directional, so a token the formatter *dropped* still fails, and added braces must balance.
- Fix formatting not being a fixed point again, in two more places: a single-statement body gained braces emitted tight, while a real block is padded with blank lines, so the second format of the same code took the padded path; and `preformat` replaced a converted element whole, so it could not descend into its body and any void element nested there survived until a later run. Non-idempotent files dropped from 390 to 36 across the corpus.
- Fix the release workflow, which had never produced a release — 23 runs, every one failed or cancelled. `darwin` was cross-compiled from Linux with zig, but CGO there links `libresolv` and the CoreFoundation and Security frameworks, and zig ships macOS libc headers without the Apple SDK that provides them, so the link failed every time. `darwin` now builds on `macos-latest`, where CGO is native, and the amd64 slice cross-compiles on the arm64 runner with an `-arch` flag. The matrix also had `fail-fast` at its default, so that one failure cancelled every other platform mid-build — `linux/amd64` had already built and packaged successfully in the last run and still uploaded nothing.
- Other release workflow changes: zig is gone, with `linux/arm64` and `windows/amd64` cross-compiling under the stock Ubuntu toolchains (which also drops `goto-bus-stop/setup-zig` and its Node 20 deprecation warning); the CFML docs are fetched and generated once in their own job and shared as an artifact, rather than refetched on all five runners; a single tag-gated job publishes every asset instead of five racing to create the same release, and it verifies all five are present first so a partial upload cannot ship a release missing a platform; each build asserts its binary really is for the target `GOARCH`; tarballs are built with `COPYFILE_DISABLE=1` so macOS `bsdtar` does not store AppleDouble `._` entries beside the binary; permissions are `contents: read` except on the publish job; a hyphenated tag such as `v1.2.3-rc1` publishes as a prerelease and never becomes "Latest"; and `workflow_dispatch` allows the whole build to be rehearsed without cutting a tag.
